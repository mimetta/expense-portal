How branch budgeting works here:
  1. Branch is a selector, not another nesting level. 50 categories across 13 branches is 650 lines; nested, the grid would be unusable. You pick a branch and edit its 50 lines, exactly as today.
  2. All branches is read-only — the sum of every branch, so you can see the whole department without leaving the page. Editing happens on a branch.
  3. (no branch) is a real bucket. Branch is optional on the submit form, so some spend belongs to no branch. It gets its own tab rather than being hidden or spread.
  4. Closed branches stay visible but are marked. DCP keeps its history and can still be opened; it just isn't somewhere new budget would normally go.
  5. A dot marks a branch with unsaved changes, so switching branches mid-edit can't lose work silently.
  6. Spend report groups by branch or by category, not both at once — branch × category × month is too much for one table.
  7. Each branch carries its own colour — a swatch, a tinted header, and a coloured left edge that stays with every row beneath it. With several branches expanded, a row is always traceable to its branch without scrolling back up. The colour is kept off the figures themselves, since those already use green/amber/red for budget use and two colour languages in one cell would fight.
